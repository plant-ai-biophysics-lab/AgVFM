## Executive Summary

**Overall Assessment:** Strong, systematic work with clear contributions to zero-shot agricultural vision. The three-phase experimental design is well-structured and addresses a real gap in the literature. The work demonstrates rigor in prompt engineering analysis and provides actionable guidance for practitioners. However, several methodological concerns and presentation issues should be addressed before publication.

**Recommendation:** **Accept with Major Revisions**

**Key Strengths:**
- Systematic, reproducible experimental framework
- Clear focus on zero-shot deployment constraints
- Architecture-specific findings with practical implications
- Comprehensive threshold sensitivity analysis

**Key Concerns:**
- Dataset size and generalizability claims
- Statistical significance and confidence intervals
- Some methodological choices need better justification
- Missing references section
- Some claims may be overstated

---

## 1. Overall Assessment

### 1.1 Strengths

**Experimental Design:**
- **Excellent systematic approach:** The three-phase design (factor analysis → combinations → threshold sweeps) is logical and builds incrementally. The OFAT (one-factor-at-a-time) analysis in Phase 1 is appropriate for isolating component effects.
- **Zero-shot focus is well-maintained:** The constraint of "no labels for tuning" is consistently respected throughout, which is critical for the target use case.
- **Model-agnostic framework:** The evaluation pipeline is appropriately designed to compare different architectures fairly.
- **Comprehensive metrics:** Reporting mAP at multiple IoUs, point metrics (P/R/F1), and counting metrics (R², RMSE, etc.) provides a complete picture.

**Technical Contributions:**
- **Architecture-specific prompt rules:** The finding that prompt engineering rules don't transfer between models is important and well-documented.
- **Threshold sensitivity analysis:** Phase 3 addresses a critical gap—most work assumes labeled validation data for threshold selection. The sensitivity analysis provides practical guidance.
- **Absorber architecture evaluation:** Testing absorber-style negation is creative and the finding that text negation outperforms absorbers is valuable.

**Presentation:**
- **Clear manuscript structure:** The manuscript flows logically from introduction through methods, results, and discussion.
- **Good use of figures:** 9 figures provide visual support for key findings.
- **Reproducibility:** The codebase appears well-organized with clear separation between library code (`agvfm/`) and experiments.

### 1.2 Major Concerns

**Dataset and Generalizability:**
- **Single species limitation:** Evaluating on only cowpea flowers is a significant limitation. The manuscript acknowledges this, but the claims about "practical guidance" may be overstated given the narrow scope.
- **Test set size:** 178 images (158 test + 20 dev) is relatively small. While this may be acceptable for a fine-grained detection task, confidence intervals should be reported to quantify uncertainty.
- **No cross-validation or statistical testing:** Results are reported as point estimates without confidence intervals or statistical significance tests. This is problematic when making claims about model differences.

**Methodological Issues:**
- **Dev set usage unclear:** The manuscript mentions "158 test + 20 dev" but doesn't clarify how the dev set is used. If it's used for any tuning or selection, this violates the zero-shot constraint.
- **Baseline prompt selection:** The choice of `"a flower"` as baseline is reasonable, but why not also test a more informative baseline like `"a cowpea flower"`? The taxonomy axis already includes this, but it's worth discussing why the generic baseline was chosen.
- **IoU threshold selection:** Multiple IoUs are reported (0.3, 0.5, 0.5:0.95), but the primary focus is mAP@0.5. For fine-grained objects, IoU=0.5 may be too lenient. The choice should be justified, or results at stricter IoUs (0.7, 0.75) should be discussed.

**Results Interpretation:**
- **mAP vs F1 disconnect:** The manuscript correctly notes that mAP measures ranking quality while F1 measures point performance, but the discussion sometimes conflates them. For example, claiming SAM3 "achieves higher mAP" while also noting it has "lower F1" needs clearer explanation of when each metric matters.
- **Threshold sensitivity interpretation:** The finding that YOLO World has "low sensitivity" (<0.02 F1 change) is good, but ±0.05 is a relatively small range. What about ±0.10 or ±0.20? The robustness claim may be overstated.
- **"Optimal" threshold discussion:** While the manuscript correctly avoids label-based threshold selection, the discussion of "optimal F1 thresholds" (0.30-0.45) could be clearer that these are post-hoc observations, not recommendations for deployment.

**Missing Elements:**
- **References section:** Completely empty. This is critical for publication.
- **Statistical analysis:** No confidence intervals, no significance tests, no discussion of variance across images.
- **Failure mode analysis:** While Phase 4 (grounding gap) is planned, some qualitative analysis of failure cases would strengthen the current work.

## 2. Detailed Technical Comments

### 2.1 Phase 1: Factor Analysis

**Strengths:**
- OFAT design is appropriate for isolating effects
- 7 axes cover relevant prompt dimensions
- Baseline prompt (`"a flower"`) is reasonable

**Concerns:**
- **Interaction effects:** OFAT cannot detect interactions. The manuscript later notes "super-additive" interactions in Phase 2, but Phase 1 results may be misleading if interactions are strong. Consider acknowledging this limitation more explicitly.
- **Taxonomy axis breadth:** 8 taxonomy values is good, but some (e.g., "vigna unguiculata flower") may be too technical for CLIP. The finding that "cowpea flower" works best is expected, but the comparison to scientific names could be more informative.
- **Size axis results:** The finding that size modifiers hurt YOLO World but help SAM3 is interesting, but the mechanism isn't explained. Is this a calibration issue, or does SAM3 interpret "tiny" differently?

**Recommendations:**
- Add confidence intervals or standard errors to factor contribution plots
- Discuss why certain taxonomy values (e.g., scientific names) underperform
- Consider a small interaction test (e.g., 2x2 factorial) to validate OFAT assumptions

### 2.2 Phase 2: Combinations & Absorbers

**Strengths:**
- Systematic combination strategy is sound
- Absorber architecture evaluation is creative
- Strategic experiments (partial negation variants) show good scientific judgment

**Concerns:**
- **Absorber failure:** The finding that absorbers perform poorly (mAP: 0.1359 vs 0.4123 for text negation) is interesting, but the explanation is brief. Why do absorbers fail? Is it because:
  - The confuser prompts are poorly chosen?
  - Multi-class detection introduces noise?
  - The filtering logic is flawed?
  - CLIP embeddings for confusers are too similar to targets?
- **Partial vs full negation:** The finding that 2-clause negation beats 3-clause negation is important, but the mechanism isn't clear. Does CLIP interpret longer negations differently? Is there a "negation fatigue" effect?
- **SAM3 negation failure:** SAM3's complete failure on complex negation is noted, but not explained. Is this a limitation of SAM3's text encoder, or a prompt interpretation issue?

**Recommendations:**
- Add qualitative analysis of absorber failures (e.g., visualize what confusers are detected)
- Test simpler absorber configurations (e.g., just "bud" vs "bud + calyx") to isolate the failure mode
- Consider testing negation with different phrasings (e.g., "excluding X" vs "not X")

### 2.3 Phase 3: Confidence Threshold Analysis

**Strengths:**
- Addresses a critical gap in zero-shot deployment
- Comprehensive threshold sweep (18 values)
- Sensitivity analysis is appropriate
- Detection volume analysis is insightful

**Concerns:**
- **Sensitivity range:** ±0.05 is a small range. What about ±0.10 or ±0.20? The "low sensitivity" claim may be overstated.
- **Optimal threshold discussion:** The manuscript identifies "optimal F1 thresholds" (0.30-0.45) but these are post-hoc. For zero-shot deployment, practitioners can't know these values. The recommendation should focus on fixed thresholds (e.g., 0.50) or unlabeled rules (top-K, percentiles).
- **mAP at low thresholds:** The finding that mAP is highest at conf=0.05-0.15 is expected (mAP rewards recall), but the manuscript sometimes implies this is "better" when it's just a property of the metric.
- **SAM3 sensitivity:** SAM3 shows "moderate sensitivity" (0.10-0.12 F1 change), which is 5-6x higher than YOLO World. This is a significant difference that deserves more discussion.

**Recommendations:**
- Report sensitivity at multiple ranges (±0.05, ±0.10, ±0.20)
- Provide unlabeled operating rules (e.g., "use top-K detections per image" or "use 75th percentile confidence")
- Add confidence distribution plots to understand why thresholds matter
- Discuss why SAM3 is more sensitive (is it calibration, or architecture?)

### 2.4 Model Comparison

**Strengths:**
- Clear comparison across multiple metrics
- Precision-recall tradeoff is well-documented
- Architecture-specific recommendations are practical

**Concerns:**
- **mAP vs F1 tradeoff:** The manuscript notes SAM3 has higher mAP (0.54 vs 0.41) but lower F1 (0.26-0.28 vs 0.36-0.40). This is confusing—why does higher mAP correspond to lower F1? The explanation (precision-recall tradeoff) is correct, but the presentation could be clearer.
- **Baseline differences:** SAM3's baseline mAP (0.3710) is much higher than YOLO World's (0.0909). This suggests SAM3 may be better calibrated initially, or the segmentation architecture is inherently better for this task. This deserves more discussion.
- **Counting metrics:** Counting metrics (R², RMSE) are mentioned but not reported in detail. For agricultural applications, counting accuracy may be more important than detection mAP.

**Recommendations:**
- Add a table comparing all metrics side-by-side for top configs
- Report counting metrics in detail (R², RMSE, MAE) for both models
- Discuss why SAM3 baseline is higher (calibration? architecture? dataset bias?)

## 3. Manuscript Quality

### 3.1 Structure and Flow

**Strengths:**
- Logical progression from introduction → methods → results → discussion
- Abstract clearly states contributions
- Methods section is detailed and reproducible

**Issues:**
- **Related Work is thin:** Only 4 paragraphs. Should expand to cover:
  - Agricultural vision papers (flower detection, counting)
  - Zero-shot detection literature
  - Prompt engineering studies
  - Confidence calibration work
- **Discussion could be deeper:** The discussion section is good but could explore:
  - Why architecture differences matter (detection vs segmentation)
  - Failure mode hypotheses (structural vs linguistic)
  - Implications for other agricultural tasks

### 3.2 Writing and Clarity

**Strengths:**
- Generally clear and well-written
- Technical terms are defined
- Figures support the text well

**Issues:**
- **Some claims are overstated:**
  - "practical, quantitative guidance" may be too strong given single-species evaluation
  - "robust for zero-shot deployment" should be qualified (robust within tested range)
- **Inconsistent terminology:**
  - Sometimes "zero-shot" vs "label-scarce" vs "no labels for tuning"
  - Standardize on one term or clearly define differences
- **Numbers need context:**
  - mAP values (0.41, 0.54) are reported without confidence intervals
  - F1 differences (0.36 vs 0.40) may not be significant

### 3.3 Figures and Tables

**Strengths:**
- 9 figures provide good visual support
- Figures are referenced in text
- Captions are informative

**Issues:**
- **Missing comparison tables:** A side-by-side table of top configs (mAP, F1, P, R, counting metrics) would be helpful
- **Figure quality:** Can't assess from markdown, but ensure figures are publication-quality (high DPI, clear labels, readable fonts)
- **Figure 2:** The combination performance figure shows YOLO World and SAM3 separately. A combined comparison would be more informative.

### 3.4 Missing Elements

**Critical:**
- **References section:** Completely empty. Must be added.
- **Statistical analysis:** No confidence intervals, no significance tests
- **Supplementary material:** Consider adding:
  - Full results tables (all configs, all metrics)
  - Failure case examples (qualitative analysis)
  - Code/data release information

**Nice to have:**
- **Ablation studies:** Why do certain components work? (e.g., why does "tiny" help SAM3?)
- **Cross-species validation:** Even a small validation on another species would strengthen claims
- **Computational cost:** How do models compare in inference time? (important for deployment)

## 4. Specific Recommendations

### 4.1 High Priority (Must Address)

1. **Add References Section:**
   - Include: YOLO World, SAM3, CLIP, agricultural vision papers, zero-shot detection work, confidence calibration papers
   - Use consistent citation style (likely CVPR format)

2. **Add Statistical Analysis:**
   - Report confidence intervals for all metrics (bootstrap or cross-validation)
   - Add significance tests for model comparisons
   - Discuss variance across images

3. **Clarify Dev Set Usage:**
   - Explicitly state that dev set is NOT used for tuning
   - If dev set is used for anything, explain how this maintains zero-shot constraint

4. **Strengthen Generalizability Claims:**
   - Acknowledge single-species limitation more prominently
   - Qualify "practical guidance" claims
   - Add discussion of when findings might generalize

5. **Expand Related Work:**
   - Add 2-3 paragraphs on agricultural vision
   - Add 1-2 paragraphs on zero-shot detection
   - Add 1 paragraph on prompt engineering

### 4.2 Medium Priority (Should Address)

6. **Improve Threshold Sensitivity Analysis:**
   - Report sensitivity at multiple ranges (±0.05, ±0.10, ±0.20)
   - Provide unlabeled operating rules (top-K, percentiles)
   - Add confidence distribution plots

7. **Add Comparison Tables:**
   - Side-by-side table of top configs (all metrics)
   - Counting metrics table (R², RMSE, MAE)
   - Threshold sensitivity comparison table

8. **Deepen Discussion:**
   - Explain why architecture differences matter
   - Hypothesize about failure modes (structural vs linguistic)
   - Discuss implications for other tasks

9. **Clarify mAP vs F1 Tradeoff:**
   - Better explanation of why SAM3 has higher mAP but lower F1
   - Clear guidance on when to optimize for each metric

10. **Add Qualitative Analysis:**
    - Show example failure cases
    - Visualize what absorbers detect
    - Analyze why certain prompts fail

### 4.3 Low Priority (Nice to Have)

11. **Cross-Species Validation:**
    - Even a small test on another species would strengthen claims
    - Could be added to supplementary material

12. **Computational Cost Analysis:**
    - Compare inference time for both models
    - Important for deployment considerations

13. **Ablation Studies:**
    - Why do certain components work? (e.g., "tiny" for SAM3)
    - Could be future work or supplementary

14. **IoU Threshold Analysis:**
    - Discuss why IoU=0.5 was chosen
    - Report results at stricter IoUs (0.7, 0.75) for fine-grained objects

## 5. Minor Issues

### 5.1 Terminology

- **"Zero-shot" vs "label-scarce":** Standardize terminology or clearly define differences
- **"Optimal threshold":** Clarify that these are post-hoc observations, not deployment recommendations
- **"Robust":** Qualify robustness claims (e.g., "robust within ±0.05 threshold range")

### 5.2 Numbers and Precision

- **Decimal places:** Be consistent (e.g., mAP reported to 4 decimals in some places, 2 in others)
- **Significant figures:** Don't report more precision than is meaningful (e.g., mAP=0.4123 vs 0.41)

### 5.3 Figure Captions

- **Figure 1:** Add note about which model is which in the plot
- **Figure 2:** Consider combining YOLO World and SAM3 into one comparison plot
- **All figures:** Ensure axis labels are clear and units are specified

### 5.4 Code/Data Availability

- **Reproducibility:** The manuscript mentions a "reproducible framework" but doesn't specify code/data release
- **Consider adding:** "Code and data will be released upon publication" or similar statement

## 6. Positive Highlights

Despite the concerns above, this is strong work with several notable contributions:

1. **Systematic prompt engineering:** The three-phase design is thorough and addresses a real gap
2. **Zero-shot focus:** The constraint is well-maintained throughout, which is critical
3. **Architecture-specific findings:** The discovery that prompt rules don't transfer is important
4. **Threshold sensitivity:** Phase 3 addresses an understudied aspect of zero-shot deployment
5. **Practical guidance:** The recommendations are actionable for practitioners

---

## 7. Final Recommendation

**Recommendation: Accept with Major Revisions**

This work has strong contributions and addresses an important problem. However, several issues must be addressed:

1. **Must fix:** References, statistical analysis, dev set clarification, generalizability claims
2. **Should improve:** Threshold sensitivity analysis, comparison tables, discussion depth
3. **Nice to have:** Cross-species validation, qualitative analysis, computational cost

With these revisions, this work would be a strong contribution to the agricultural vision and zero-shot detection communities.
